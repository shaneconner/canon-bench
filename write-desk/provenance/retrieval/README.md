# The retrieval benchmark, frozen

The offline known-item benchmark in this programme measured two real project
stores. It read them at their paths and derived its query set when it ran, so
both the corpus and the query population moved as the projects were used. That
is a reproducibility defect and it was found by external review rather than by
us. This directory is the repair and the measurement of what the defect cost.

## What the defect cost

`r1_freeze.mjs` reads the two stores once and writes a single artifact carrying
every document's indexed text, the derived eligible queries with their resolved
targets, the deterministic sample, and both query variants.
`r1_frozen_score.mjs` reads that artifact and opens nothing else.

Scoring the frozen corpus against the numbers the paper plots, which came from a
store state that no longer exists:

| store / variant / surface | BM25 then | BM25 frozen | change | embed then | embed frozen | change |
|---|---|---|---|---|---|---|
| quorum full art-only | 0.688 | 0.593 | -0.095 | 0.413 | 0.415 | +0.002 |
| quorum full mixed | 0.558 | 0.425 | -0.133 | 0.203 | 0.195 | -0.008 |
| quorum terse art-only | 0.440 | 0.378 | -0.062 | 0.233 | 0.245 | +0.012 |
| quorum terse mixed | 0.280 | 0.243 | -0.037 | 0.118 | 0.118 | 0.000 |
| pi-fold full art-only | 0.830 | 0.797 | -0.033 | 0.642 | 0.654 | +0.012 |
| pi-fold full mixed | 0.566 | 0.481 | -0.085 | 0.387 | 0.398 | +0.011 |
| pi-fold terse art-only | 0.632 | 0.564 | -0.068 | 0.519 | 0.519 | 0.000 |
| pi-fold terse mixed | 0.255 | 0.233 | -0.022 | 0.160 | 0.113 | -0.047 |

Read the two change columns against each other. BM25 fell in eight of eight
cells, by 2.2 to 13.3 points. The embedding ranker moved between -4.7 and +1.2
and has no sign to it. The stores grew between the two runs, `quorum` from 742
articles and 1,402 journal entries to 744 and 1,411 and `pi-fold` from 56 and
136 to 58 and 166, and almost all of that growth is journal entries sharing
vocabulary with the articles they concern. The earlier decomposition in
`../../RANKING-RESULTS.md` already found journal crowding to be the largest
recoverable loss for the lexical ranker, so crowding is the candidate
explanation and it is consistent with the direction. It is not isolated here and
we do not claim it is.

**The ordering held in eight of eight cells.** BM25 still beats cosine over
local embeddings everywhere, at margins that compressed from 9.5 to 35.5 points
down to 4.5 to 23.0. That is the same shape as this programme's central result:
the direction survives a re-run and the size does not.

## Positive control

`r1_frozen_score.mjs` also scores an oracle ranker that puts each query's own
targets first, and refuses to print anything unless the oracle reaches 1.0 in
every cell. A ranking bug that returned nothing would otherwise print zeroes,
and zeroes would read as a finding. The oracle is at 1.0 in all eight.

## Files

| file | what it is |
|---|---|
| `r1_freeze.mjs` | writes the immutable artifact from the two live stores |
| `r1_frozen_score.mjs` | scores that artifact and nothing else, with the oracle control |
| `r1_embed.mjs` | the original live-store harness, kept so the two can be compared |
| `frozen-scores.json` | the frozen run's output, the source of the table above |
| `frozen-corpus.sha256` | the artifact's digest, so the scores above are pinned to one corpus |

## The corpus itself is not published here

`frozen-corpus.json` is 7.9 MB and contains the full text of two real, private
project-memory stores. Publishing it would publish their contents, which is a
disclosure decision separate from anything this benchmark needs, and it has not
been made. The digest is published so the scores are pinned, and the artifact
can be regenerated by anyone with the stores using the command below. Whether it
ships with the Zenodo deposit is open.

```
node lab/ranking/r1_freeze.mjs 400
node lab/ranking/r1_frozen_score.mjs
```
